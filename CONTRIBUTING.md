# Contributing

Thank you for contributing to this project.

## Before you start

- Check existing issues and pull requests before opening a new one.
- For security vulnerabilities, follow the instructions in [SECURITY.md](SECURITY.md) instead of opening a public issue.
- Keep changes focused and avoid unrelated modifications.

## Development

1. Fork the repository or create a working branch.
2. Make your changes.
3. Test the integration with a current supported Home Assistant version.
4. Update documentation when behavior or configuration changes.
5. Use clear, descriptive commit messages.

## Pull requests

Please use the pull request template and include:

- A clear description of the change and its purpose.
- Testing performed and relevant Home Assistant/integration versions.
- Any documentation or configuration changes required.
- Any known limitations or follow-up work.

Keep pull requests focused on a single change where practical. Maintainers may request changes before merging.

## Issues

Use the appropriate issue template when reporting bugs or requesting features. Include enough detail to reproduce a problem or understand the proposed change.

Please do not include passwords, API keys, tokens, personal information, or other sensitive data in issues or pull requests.

## Code quality

- Follow the existing project structure and coding style.
- Prefer small, maintainable changes.
- Do not commit generated files, local configuration, or secrets.
- Preserve backward compatibility where practical.

By contributing, you agree that your contributions are provided under the project's MIT License.
